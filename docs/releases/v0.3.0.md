# MDStandardsKit v0.3.0

## 升级前必读

- **旧二进制 + 新 policy 会 exit 2。** 本版本随附的 `policy/data/standard.json` 使用
  `standard_version: 2`；旧二进制只接受 `1`，会在求值前失败。升级二进制与 policy 必须同批。
- **旧二进制无法读取多类型配置。** `.mdstandards.json` 若写成 `{"types":[...]}`，旧二进制会因
  未知键 exit 2。回滚时把配置改回 legacy `{"type":"spec"}` / `{"type":"idea"}`。
- **`standard.json` 改为严格字段校验。** 未知字段、尾随数据、非法 `rule_set` 或非法 `graph`
  组合都会 exit 2，不再静默忽略。
- 新二进制接受 `standard_version: 1` 与 `2`；multi 模式要求 `2`。

## 新增：多文档类型路由

- `.mdstandards.json` 新增 `{"types":[...]}`，按每个文件 frontmatter 的 `type:` 逐文件路由。
- 每个类型用 `rule_set` 选择 `spec` / `idea` / `none`；`graph: true` 的类型参与零依赖边断言。
- 缺失、未知、未启用或与路径不兼容的 `type:` 产生 routing error：phase 0 只报告，
  phase ≥ 1 未降级时 exit 2。
- 发现范围始终包含顶层 `governed_globs`；缩小 `types` 不会让这些文件静默消失。
- `--policy-from-head` 同时从 HEAD 读取 policy 与 `.mdstandards.json`。
- legacy `{"type":"spec"}` / `{"type":"idea"}` 的行为、退出码与 `-dump-corpus` 输出保持不变。

## 迁移

1. 升级二进制与 policy，确认 `policy/data/standard.json` 为 `standard_version: 2`。
2. 用 `{"types":[...]}` 替换 legacy 配置，列出仓库实际出现的全部类型。
3. 为受管文件补齐 `type:`，确保路径命中该类型 globs。
4. 先跑 `-phase 0` 修完 routing error，再切 `-phase 1`。

完整说明见 [README](../../README.md) 与 [SPEC-003](../specs/SPEC-003-multi-type/spec.md)。
