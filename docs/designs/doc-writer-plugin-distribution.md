Supersedes: 仅取代 `docs/designs/doc-writing-skill.md` 中「分发与迁移」一节；`maintainer-main-design-20261101-200200.md` 为同分支上一份设计，不整体取代。

## Problem Statement

doc-writer 现在只存在于本仓库的 `.claude/skills/doc-writer/`，其他项目要用只能手工复制，版本无法固定，也无法判断某次检查用的是哪一版规范。用户的原话：

> "我要把这个技能安装到全局供所有的项目使用，同时，我需要做到版本控制，所以他是一个能够release的技能"

真正缺的不是一个更好的复制脚本，而是三件事同时成立：

1. 任意项目里能直接调用同一份技能；
2. 安装的是某个明确的版本，升级是显式动作；
3. 发布流程能证明"这个 tag 的安装物真的能用"。

现状有两个会直接挡住第一个 tag 的问题：release 只上传旧的 `doc-writer-skill.tar.gz`，没有可安装的插件；`SKILL.md` 写死了 `<MDStandardsKit>` 路径，装好了第一次调用工具仍会失败。

## What Makes This Cool

把"一个我复制的技能"变成"一条有版本、可回滚、跨项目复用的闸门运行时"。

装好之后，target-repo 里写 Spec 用的规范、`mdstandards` 元数据闸门、`qualitycheck` 证据审计来自同一个发布版本；换一台机器、换一个项目，`claude plugin marketplace add ...#v0.1.0` 就能回到完全相同的组合。版本号不再是仓库里一个装饰字段，而是安装路径、缓存路径和 CI 验收共同引用的事实。

## Constraints

- 版本单位是整包：技能 + `policy/` + `mdstandards` + `qualitycheck` 一起发布，单仓库单一 semver。
- 全局安装走 Claude Code 插件 + marketplace（user scope），不再往 `~/.claude/skills/` 复制目录。
- 插件不打包 30MB 二进制；CI 产出 per-platform 资产，shim **下载优先、校验 sha256、Go build 兜底**。
- 固定版本 = marketplace 指向某个 tag；没有安装时按单插件版本固定的语法。
- 验收项目是 target-repo：先移除项目级技能副本，再跑通 `mdstandards -phase 1`。
- 现有 `doc-writer-skill.tar.gz` 在 v0.1 删除；README、release workflow 与旧设计文档中的分发承诺同步移除，不保留第二条安装路径。
- `${CLAUDE_PLUGIN_ROOT}` 只在技能正文里内联替换，不会进入 Bash 进程环境；shim 必须从 `$0` 推导根目录。

## Premises

1. 版本单位是整包，不做 skill 独立版本。
2. 全局安装走插件 + marketplace，user scope。
3. 二进制策略：下载优先、sha256 校验、Go build 兜底（会话中由"Go 构建优先"修订而来）。
4. 固定版本发生在 marketplace 的 ref/tag 层。
5. target-repo 先删项目级副本，再验收。
6. 旧 `doc-writer-skill.tar.gz` 在 v0.1 删除，不保留离线人工下载路径。

## Cross-Model Perspective

独立 Claude 子代理冷读的要点：

- 更酷的版本不是"版本化技能目录"，而是"版本化闸门运行时"：全局插件负责运行，项目用 `.mdstandards.lock` 固定 tool 版本与 policy sha256，这样 target-repo 可以停在 v0.1，另一个项目用 v0.3。这是本次不做的 v0.2 方向。
- 最兴奋的点是"供所有的项目使用"；发布和版本是手段，周末应优先一键安装、可见升级、target-repo 验收。
- 现成工具覆盖一半：GoReleaser 覆盖跨平台构建/校验和/Release，Anthropic 插件示例覆盖 manifest/catalog/安装 UX。剩余一半是 glue，不值得再引入 GoReleaser。
- 周末应先做：根级 `.claude-plugin/{plugin.json,marketplace.json}`、两个 shim、单一版本源、tag 一致性校验、tag 安装 smoke。
- 两个 Critical：旧的 tarball 不是可安装物；`SKILL.md` 的写死路径会让第一次工具调用失败。
- 修正其两处事实偏差：marketplace 插件技能带命名空间，不会自动恢复 `/doc-writer`；`claude plugin tag` 生成的是 `doc-writer--v0.1.0`，不是 `v0.1.0`，因此 `#v0.1.0` 固定必须由我们自己打 `v*` tag。

## Approaches Considered

### Approach A: 最小可用 —— 根级插件 + 本地构建 shim

技能移到 `skills/doc-writer/`，根级 `.claude-plugin/{plugin.json,marketplace.json}`，`bin/mdstandards` / `bin/qualitycheck` 首次调用 `go build` 到 `~/.cache/mdstandards/<ver>/`。Effort S/M，Risk Low。否决理由：每台机器都要 Go，且 `qualitycheck` 仍不预编译；只能作为"今天必须发"的兜底。

### Approach B: 根级插件 + 双工具下载 shim + tag 契约（已选）

A 的基础上，CI 同时构建 `mdstandards` 和 `qualitycheck`，发布 per-platform 资产与 `checksums.txt`；shim 顺序 `MDSTANDARDS_BIN` → 缓存 → 下载并校验 sha256 → `go build` 兜底。CI 强制 `plugin.json.version == tag`，并加干净 HOME 的安装/运行 smoke。

### Approach C: B + 项目锁文件 `.mdstandards.lock`

每个项目用锁文件固定 tool 版本、policy sha256、规则 ID；技能先读锁文件，shim 解析到对应版本；报告带版本；可选 PostToolUse hook 自动跑 phase 0/1。Effort L，Risk Med/High。本次不做，留作 v0.2 的复现性增量。

## Recommended Approach

B。它直接满足"所有项目 + 版本控制 + 可 release"，并且只解决两个会挡住第一个 tag 的 Critical 问题。C 的锁文件值得做，但它需要在 B 的 shim 和缓存机制之上再长一层，放进 v0.1 只会让第一版无法验证。

### 目标目录结构

```text
.claude-plugin/
├── plugin.json          # name: doc-writer, version: 0.1.0（唯一版本源）
└── marketplace.json     # name: mdstandards, plugins: [{name: doc-writer, source: "./"}]
bin/
├── doc-writer-tool      # 单入口 dispatcher（mdstandards | qualitycheck）
└── _resolve.sh          # 版本、缓存、下载、校验、构建
scripts/
└── shim-test.sh         # PR 级 shim 行为测试
skills/
└── doc-writer/          # 从 .claude/skills/doc-writer 移入（18 个文件）
    ├── SKILL.md
    └── spec/...
policy/                  # 原样保留，随插件根一起分发
tools/qualitycheck/      # 原样保留
main.go / extract.go / normalize.go / report.go
```

插件根 = 仓库根，`source: "./"`。这样一次安装同时拿到技能、policy 和工具源码；`${CLAUDE_PLUGIN_ROOT}` 指向缓存中的整棵仓库。

### SKILL.md 路径改写

- 所有工具调用统一为 `${CLAUDE_PLUGIN_ROOT}/bin/doc-writer-tool <tool> ...`，包括 SKILL.md 第 41 行原先是裸 `qualitycheck -audit` 的那一处。
- `<MDStandardsKit>/mdstandards` → `${CLAUDE_PLUGIN_ROOT}/bin/doc-writer-tool mdstandards`
- `<MDStandardsKit>/qualitycheck` → `${CLAUDE_PLUGIN_ROOT}/bin/doc-writer-tool qualitycheck`
- `-policy <MDStandardsKit>/policy` → `-policy "${MDSTANDARDS_POLICY_DIR:-${CLAUDE_PLUGIN_ROOT}/policy}"`。`mdstandards` 本身不读环境变量，由 shell 展开。若设置 `MDSTANDARDS_POLICY_DIR`，必须同时设置 `MDSTANDARDS_ALLOW_POLICY_OVERRIDE=1`，否则 shim exit 2；成功覆盖时 stderr 打印 warning，并在 `--version` 输出 policy sha256。
- rubric 路径 → `${CLAUDE_PLUGIN_ROOT}/skills/doc-writer/spec/quality/rubric.v1.yaml`
- 删除 `go run ./tools/qualitycheck`、`go build ./tools/qualitycheck`、"二进制用 `make build` 生成"等目标仓库内不存在的说明；贡献者构建方式只写在 `CONTRIBUTING` 或 README。

### shim 契约

单入口 `bin/doc-writer-tool`，`bin/_resolve.sh` 承担版本、缓存、下载、校验、构建。入口先解析 `$0` 与 symlink，**先算 `_root` 再 source `_resolve.sh`**，避免 `set -u` 下 `_root` 未定义。入口骨架：

```sh
#!/bin/sh
set -eu
self=$0
while [ -h "$self" ]; do
  d=$(cd -P "$(dirname "$self")" && pwd)
  self=$(readlink "$self")
  case $self in /*) ;; *) self=$d/$self;; esac
done
bin=$(cd -P "$(dirname "$self")" && pwd)
_root=$(cd -P "$bin/.." && pwd)
. "$bin/_resolve.sh"
resolve_and_exec "$@"
```

`_resolve.sh` 从 `$1` 取 tool 名并 shift；只使用入口设置的 `bin` 与 `_root`。解析顺序：

1. `$MDSTANDARDS_BIN/<tool>`：已设置但文件不可执行 → 直接 exit 2，不回退，避免静默用错版本。
2. `~/.cache/mdstandards/<version>/<os>-<arch>/<tool>`：命中即执行。
3. 从 `${MDSTANDARDS_RELEASE_BASE_URL:-https://github.com/dream-365/MDStandardsKit/releases/download/v<version>}` 下载（设置 `MDSTANDARDS_SKIP_DOWNLOAD=1` 时跳过本步，直接进入第 4 步）：先 `mkdir -p <cache>`；取 `checksums.txt`，用 `awk '$2==asset{print $1}'` 按资产名匹配 sha256；下载到 `<cache>` 内的 `mktemp` 临时文件，`chmod 0755`，校验通过后同目录 `mv` 原子替换，最后执行。下载器优先 `curl -fL`，没有则 `wget -qO-`；校验器优先 `sha256sum`，没有则 `shasum -a 256`。
4. `CGO_ENABLED=0 go build -trimpath -ldflags="-s -w"` 兜底，要求 Go ≥ 1.27.1（`go.mod` 的 `go 1.27.1`），且需要模块网络或本地 module cache：
   - `mdstandards`：在插件根执行 `-o <cache>/mdstandards .`
   - `qualitycheck`：在插件根执行 `-o <cache>/qualitycheck ./tools/qualitycheck`

两个工具增加 `--version`：输出发布版本 + policy sha256（构建时注入 policy 目录哈希），用于回答"这次检查用的是哪一版规范"。

入口解析出的 `_root` 不依赖 `CLAUDE_PLUGIN_ROOT`/`CLAUDE_PLUGIN_DATA` 环境变量。`version` 从 `$_root/.claude-plugin/plugin.json` 用 `sed -n 's/.*"version"[[:space:]]*:[[:space:]]*"\([^"]*\)".*/\1/p' | head -1` 读取。

**资产后缀统一用 Go 的 `amd64`/`arm64`**，CI、`checksums.txt`、下载 URL、缓存路径四处同名。`uname` 到后缀的映射表：

| `uname -s` | `uname -m` | 资产后缀 |
| --- | --- | --- |
| Darwin | arm64 | `darwin-arm64` |
| Darwin | x86_64 | `darwin-amd64` |
| Linux | x86_64 | `linux-amd64` |
| Linux | aarch64 | `linux-arm64` |

其他组合（含 Windows）：不进入下载或构建，直接 exit 2，并打印"该平台不在 v0.1 支持范围（darwin/arm64、darwin/amd64、linux/amd64、linux/arm64）；请手工执行 `go build`，或改用受支持平台"。POSIX shim 本身无法在 cmd/PowerShell 中运行，因此 Windows 没有可用的 shim 路径。

**失败矩阵**：

| 情况 | 行为 |
| --- | --- |
| `MDSTANDARDS_BIN` 已设但目标缺失/不可执行 | exit 2，不回退 |
| `MDSTANDARDS_POLICY_DIR` 已设但无 `MDSTANDARDS_ALLOW_POLICY_OVERRIDE=1` | exit 2，提示显式允许 |
| 下载 404、非 2xx、超时 | 进入第 4 步；无 Go 则 exit 2 |
| checksum 不匹配 | 删除临时文件，**不执行、不回退到构建**，exit 2 |
| 不支持的平台 | exit 2，打印受支持平台列表与手工构建指引；不进入下载或构建 |
| 缓存目录不可写 | exit 2，打印路径与权限提示 |
| 并发首次使用 | 临时文件在缓存目录内，校验后同目录 `mv` 原子替换；后到者命中缓存 |
| `go build` 失败 | exit 2，保留 Go 的 stderr |

所有 exit 2 的 stderr 第一行统一为 `doc-writer toolchain: <原因>`，与 mdstandards 的"工具错误 exit 2"语义一致。

### 发布与安装流程

版本规范：`plugin.json` 是唯一版本源，写 `0.1.0`（无 `v`）；git tag 和下载 URL 用 `v0.1.0`。CI 比较时先去掉 tag 的 `v` 前缀。发布后的 tag 与 Release 资产不可变；需要修正时发新版本，不移动旧 tag。

发布：

```bash
# 修改 .claude-plugin/plugin.json 到 0.1.0
make check
git add .claude-plugin/plugin.json
git commit -m "release: v0.1.0"
git push origin main
git tag v0.1.0
git push origin v0.1.0
```

CI（`release.yml`，on `v*`）按依赖顺序分四个 job，全部显式 `needs:`：

1. `verify`：tag 去 `v` 后与 `plugin.json.version` 比较，不一致 exit 1；在 tagged commit 上跑 `make check`（含 `go test ./...`）；`claude plugin validate .`（CI 里 `npm i -g @anthropic-ai/claude-code@2.1.292`）。
2. `build`（`needs: verify`）：`setup-go` 固定 `1.27.1`；矩阵 `darwin/arm64`、`darwin/amd64`、`linux/amd64`、`linux/arm64`，同时构建 `mdstandards` 与 `qualitycheck`，上传为 workflow artifact。
3. `smoke`（`needs: build`，两腿矩阵）：从 workflow artifact 取资产，设置 `MDSTANDARDS_RELEASE_BASE_URL` 指向测试用本地 HTTP 服务；`no-go` 腿在不装 Go 的容器里只走下载；`with-go` 腿 checkout tag、装 Go、设置 `MDSTANDARDS_SKIP_DOWNLOAD=1` 并清空缓存走 build；两腿都跑 `mdstandards -root <checkout>/testdata/example-repo -policy <plugin-root>/policy -phase 1`，并断言产物来源（下载腿 sha256 等于 artifact；构建腿断言缓存由 `go build` 生成，而不是预置文件）。
4. `publish`（`needs: smoke`）：汇总 artifact，生成 `checksums.txt`（按资产名排序），创建 GitHub Release 并上传。smoke 失败时不会发布。

PR CI（`ci.yml`）新增：`claude plugin validate .` + `scripts/shim-test.sh`，覆盖缓存命中、下载校验、checksum 不匹配、404→构建、无 Go→exit 2、symlink/PATH 调用、cache-miss 构建。

跨版本 upgrade/rollback smoke 只在 `v0.2.0` 及以后运行：v0.1.0 时 v0.2.0 尚不存在，workflow 用 `if: startsWith(github.ref_name, 'v0.1.') == false` 跳过并打印原因。

安装（user scope）：

```bash
claude plugin marketplace add dream-365/MDStandardsKit#v0.1.0 --scope user
claude plugin install doc-writer@mdstandards --scope user
```

`#<ref>` 固定 marketplace 目录到 tag；`install` 默认就是 user scope，这里显式写出。依据：官方 marketplace 文档明确支持 `owner/repo#<ref>`；本机 Claude Code 2.1.292 的 `marketplace add --help` 与 `install --help` 均包含 `--scope`。调用名是 `/doc-writer:doc-writer`（插件命名空间），这是接受插件机制的代价。v0.1 固定用 `doc-writer` 作为插件名；改成 `mdstandards` 以获得 `/mdstandards:doc-writer` 是 post-v0.1 的可选项，会改变安装命令。

升级/回滚 = 重指 marketplace。注意 `marketplace remove` 会卸载插件并删除其 data/options/secrets，所以这是"卸载再装"，不是无缝热更新：

```bash
claude plugin marketplace remove mdstandards
claude plugin marketplace add dream-365/MDStandardsKit#v0.2.0 --scope user
claude plugin install doc-writer@mdstandards --scope user
```

回滚把 `v0.2.0` 换成 `v0.1.0` 重复同一序列。`claude plugin update` 用于 marketplace 跟踪 `main` 的场景，不用于 pinned tag。

## Open Questions

1. v0.2 的 `.mdstandards.lock` 格式：只锁 tool 版本，还是同时锁 policy sha256 与规则 ID？倾向三者都锁。
2. post-v0.1 是否把插件名从 `doc-writer` 改为 `mdstandards`，换取 `/mdstandards:doc-writer` 的调用名？会改变安装命令，需要一次迁移说明。
3. Windows 何时纳入？v0.1 明确不支持，shim 会给出受支持平台列表与手工构建指引。

## Success Criteria

- 干净 HOME 下 `claude plugin marketplace add dream-365/MDStandardsKit#v0.1.0 --scope user` 与 `claude plugin install doc-writer@mdstandards --scope user` 成功。
- 在任意非本仓库目录能加载技能；`/doc-writer:doc-writer` 可用。
- 支持平台（darwin/arm64、darwin/amd64、linux/amd64、linux/arm64）上，无 Go 的机器首次调用 shim 能下载并通过 sha256 校验；`with-go` 腿通过 `MDSTANDARDS_SKIP_DOWNLOAD=1` 强制验证 build fallback；不支持平台给出受支持平台列表与手工构建指引并 exit 2。
- target-repo：删除 `.claude/skills/doc-writer` 后，技能仍可用；架构文档转 `Approved`，第一份带真实 `depends_on` 的 Spec 跑 `<plugin-root>/bin/doc-writer-tool mdstandards -root . -policy <plugin-root>/policy -phase 1` 退出 0。`<plugin-root>` 由技能在执行时用 `${CLAUDE_PLUGIN_ROOT}` 内联替换。
- CI 在 tag 与 `plugin.json.version` 不一致时失败；两个工具的四平台资产与 `checksums.txt` 都存在；`claude plugin validate .` 通过；smoke 在发布前通过；`doc-writer-tool mdstandards --version` 与 tag 一致并输出 policy sha256。
- v0.1.0 验证同版本安装；从 v0.2.0 起，升级到新版本的"remove → add → install"序列和回滚序列都在 smoke 中实际跑过。

## Distribution Plan

- 渠道：GitHub 仓库作为 marketplace（`dream-365/MDStandardsKit`），插件 `doc-writer@mdstandards`，user scope。
- 资产：`mdstandards-<os>-<arch>`、`qualitycheck-<os>-<arch>`、`checksums.txt`，随 `v*` Release 发布；支持平台为 darwin/arm64、darwin/amd64、linux/amd64、linux/arm64。
- 用户不需要手动 clone；`marketplace add` 会克隆仓库目录，插件缓存到 `~/.claude/plugins/cache/<marketplace>/<plugin>/<version>/`。
- 自动更新默认关闭；升级是显式重指 tag，符合"版本控制"。发布后的 tag 与 Release 资产不可变。
- `MDSTANDARDS_RELEASE_BASE_URL` 是文档化的下载基址覆盖，用于镜像、离线缓存和发布前 smoke；默认指向 GitHub Release。
- 旧 `doc-writer-skill.tar.gz` 在 v0.1 删除；README 的安装章节改为插件路径，不再保留离线 tarball 说明。
