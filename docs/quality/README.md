# Quality reports

Each target has two forms:

- `quality-report.md` / `quality-findings.json` — a real independent reviewer pass using `reviewer.md` and `rubric.v1.yaml`.
- `quality-report.smoke.md` / `quality-findings.smoke.json` — a zero-level pipeline smoke test. It proves the tool runs, not the content quality of the target.

The separation between the real specs (91.0 and 93.3) and the two non-spec documents (15.0 and 12.0) is the signal the scorecard is meant to provide. The real reviewer pass is independent of the writer; the auditor verifies evidence presence, section placement, and score arithmetic, not whether evidence is sufficient or true.

These real passes used rubric 1.0.0, archived at `skills/doc-writer/spec/quality/archive/rubric.v1.0.0.yaml`. Rubric 1.1.0 adds `arch.references_source`, so their findings remain historical records and need a fresh independent pass before audit or calibration against the current rubric.

The calibration set in `skills/doc-writer/spec/quality/calibration/gold.v1.json` stays pinned to rubric 1.0.0. SPEC-001's 2026-11-02 pass is archived; the two candidate entries keep their original findings. All three need re-review and re-adjudication against 1.1.0 before use.

## Smoke reports

The `.smoke` files cover the same targets and are regenerated byte-for-byte by `TestSmokeReportsReproduce`. They are pipeline tests, not verdicts.

The real review writes `quality-findings.json` / `quality-report.md` (without `.smoke`) using `reviewer.md` and `rubric.v1.yaml`.

## Idea reports

Idea reports live in the ideas repo at `docs/quality/ideas/<id>/` and use the same file names. They use
`skills/idea-writer/idea/quality/rubric.v1.yaml`; the headline is 推进就绪度, while maturity and
非显而易见 are diagnostic. The 2026-11-02 pipeline smoke run for 万花筒 produced headline 25.0,
diagnostic 35.0, and no audit failures; it validates the pipeline, not the rubric's calibration.
