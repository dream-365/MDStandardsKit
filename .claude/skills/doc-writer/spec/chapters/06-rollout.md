# 第 6 章：上线与迁移计划

目标：回答"怎么平滑换上去、历史数据怎么过渡、崩了怎么逃生"。

## 四个板块

1. **发布与灰度**：全量、蓝绿、金丝雀、Feature Flag；灰度节奏与观察期。
2. **数据迁移与兼容**：向后兼容（新增字段允许 Null，不直接删改旧字段）；Backfill、双写、影子表。
3. **上线验证与冒烟**：健康检查、核心链路冒烟、监控观察期。
4. **回滚与灾难恢复**：回滚触发条件、回滚步骤、数据库兼容降级。

## 模板

```markdown
## 6. 上线与迁移计划

### 6.1 发布与灰度
采用分阶段金丝雀：
* Phase 1：Staging 集成测试与核心链路回归。
* Phase 2：5% 生产流量观察 24 小时。
* Phase 3：无异常后放量至 50%、100%，下线旧逻辑。

### 6.2 数据迁移与兼容
* **Schema 演进**：Expand-Contract。新增 `document_nodes` 不影响旧表。
* **历史数据**：不全量迁移；旧文档懒加载或异步回填。

### 6.3 上线验证与冒烟
* 冒烟：WebSocket 连接与鉴权；提交 10 页 PDF，验证流式响应与 Checkpoint 落库。
* 观察指标：`error_rate`、`parser_latency_p99`、`sqlite_busy_count`。

### 6.4 回滚与熔断
* **触发条件**：核心接口错误率连续 3 分钟 > 2%；连接池耗尽或 OOM。
* **回滚步骤**：CI/CD 一键回滚上一稳定镜像；网关灰度权重调回 0%；非破坏性字段扩展，无需回滚数据库。
```

## 避坑

- 没有回滚计划的上线等同赌博；回滚步骤要像操作手册，最好一键。
- 忽视数据兼容是最常见的回滚失败原因：新代码写入旧系统不认识的字段，回滚后数据污染。
- 回滚触发条件必须是可观测的数字，不是"感觉不对"。

## 检查

- 有发布策略与灰度节奏。
- 有数据迁移/兼容方案，或说明无需迁移。
- 有冒烟清单与观察指标。
- 有回滚触发条件与步骤，不只写"可以回滚"。
