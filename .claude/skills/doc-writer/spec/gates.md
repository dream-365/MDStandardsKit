# Spec 闸门

一次只问一个问题，等到回答再问下一个。答案必须落到文档里，不能只停在对话里。

## 最小集（缺一不可）

### 背景（落到 1.1-1.4）

1. 现状是什么？相关模块或服务现在负责什么，核心流程怎么走？
2. 触发点是什么？为什么现在做，而不是上季度或下季度？
3. 谁被卡住？具体的人、角色或下游系统，不要写"用户"。
4. 不做的后果是什么？继续维持现状会发生什么？

### 痛点（落到 1.2）

5. 失败链是什么？从触发到后果，一步一步写。
6. 有没有一次具体事故、度量或引述？没有证据就继续问，不接受"性能不好""代码很乱"。

## 方案问题（过关后才问）

7. 目标是否可量化？每个 Goal 的验收方式是什么？
8. 非目标是什么？标 `本次不做` 或 `Deferred to Phase 2`，不要写 `永远不做`。
9. 备选方案有哪些？必须包含 Status Quo 和至少一个被否决方案。
10. 上线与回滚：回滚触发条件是什么？不要只写回滚步骤。

## 跳过规则

- 用户说"先跳过"时，记录跳过原因，但不解锁方案章节。
- 最小集任一未答完，输出 Gate Report 并停止；不创建、不修改 `spec.md`。
- 非最小问题可以记为 open question，不阻断方案章节；起草后写进 `## 附录 A：未决问题`。

## Gate Report

```text
route: spec
target: <spec.md 路径>
answered: <已答项>
missing: <缺失的最小项>
next question: <下一问>
```
