# 第 2 章：目标与非目标

目标：把背景里的痛点，翻译成本次明确要做到什么、明确不做什么。

## 目标

分三类写，每条都要可验证：

- **架构/代码级**：组件解耦、领域模型、接口抽象、消除循环依赖。
- **性能/指标级**：吞吐、延迟、资源占用、并发。
- **可靠性/运维级**：断点续传、链路追踪、无损迁移。

用 SMART：差的是"提升解析性能和稳定性"；好的是"单页 PDF 平均解析延迟降到 < 500ms，算子异常时支持节点级 Checkpoint 恢复"。

单次 Spec 的 Goals 控制在 3-6 个；超过说明范围过大，应拆成多个子 Spec。

## 非目标

非目标是防御性边界，不是"永远不做"清单。常见类型：

1. **上下游演进**：本次只改后端，不改前端阅读器。
2. **算法/引擎**：不改进 OCR 精度，只重构流水线。
3. **高级特性延后**：多机房多活留待 Phase 2。
4. **边缘/低频场景**：不支持加密 PDF，直接返回错误码。

每条标 `本次不做` 或 `Deferred to Phase 2`。不要写 `永远不做`；也不要让 Non-Goals 变成"看起来相关但没想清楚"的垃圾桶。

## 模板

```markdown
## 2. 目标与非目标

### 2.1 目标
- **G1 - 架构解耦**：抽象 `Document` 领域模型，解耦解析管线与存储后端。验收：<test/指标>。
- **G2 - 扩展能力**：新增格式只需实现 `BaseParser`。验收：<新增一个格式的工时/用例>。
- **G3 - 性能与高可用**：异步流式处理 + 节点级 Checkpoint。验收：<P99/恢复时间>。
- **G4 - 可观测性**：每页/每段有 Trace ID。验收：<看板/日志字段>。

### 2.2 非目标
- **NG1 - 算法升级**：不调 OCR/Layout 精度（本次不做）。
- **NG2 - 前端变更**：不改 WebSocket 协议，保持向后兼容（本次不做）。
- **NG3 - 多租户 RBAC**：留待 Phase 2（Deferred to Phase 2）。
```

## 检查

- 每个 Goal 有验收方式，不是"提升/优化"。
- Goals 数量 3-6 个。
- 每个 Non-Goal 标了 `本次不做` 或 `Deferred to Phase 2`。
- 后续章节能逐条呼应 Goals。
